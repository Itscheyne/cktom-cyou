# modules/secret_consumption

Demonstrates how IaC consumes blind secret references generated by
`scripts/secret_create.py`. The agent knows the reference (a SOPS file
path + key), never the plaintext value.

## How it works

1. Agent calls `scripts/secret_create.py` (via stdin JSON).
2. Broker generates entropy, writes a SOPS-encrypted `secrets/<env>/<name>.secrets.yaml`, returns a reference like `sops://secrets/prod/rds-app-db.secrets.yaml#secret_value`.
3. Agent writes that reference as a variable in the IaC.
4. At plan/apply time, CI (which holds the age private key) decrypts and injects the value.

## Usage

```hcl
module "db_secret" {
  source = "./modules/secret_consumption"

  secret_file = "secrets/prod/rds-app-db.secrets.yaml"
  secret_key  = "secret_value"

  # Pass the resolved value to a Proxmox cloud-init or similar.
  # The value is marked sensitive and never printed.
}
```

## State leak warning

Any secret value resolved at plan/apply time appears in `.tfstate`.
Prefer passing the reference to a runtime workload and letting it resolve
via SOPS/age directly (zero state exposure). Only use this module when the
resource genuinely requires the plaintext at apply time.

See `docs/blind-secret-management.md` §7 for the full threat model.
