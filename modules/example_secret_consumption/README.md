# Example Secret Consumption Module

This example module demonstrates how to consume "blind" secret references (e.g., an AWS Secret ARN or a Vault path) generated by an agent. The core principle is that the deployment environment knows *where* to get the secret, but the plaintext value is never hardcoded in the source code.

## Key Concepts Demonstrated

1. **Blind Input Variables**: Instead of `variable "db_password" { type = string }`, the module accepts `variable "db_password_secret_arn" { type = string }`. The agent or orchestrator only needs to pass the safe reference identifier.
2. **Secure Fetching**: We use native data sources (`aws_secretsmanager_secret_version`, `vault_generic_secret`) to resolve the reference at apply-time.
3. **Usage in Resources**: The fetched value is securely injected into infrastructure (e.g., RDS `password` field, or an SSM Parameter Store).
4. **Lifecycle Hooks**: `ignore_changes = [password]` is often used for RDS so that modifying the password out-of-band or token resets don't trigger unnecessary drift or replace operations.
5. **Sensitive Outputs**: Any outputs that forward the raw token/password explicitly declare `sensitive = true` to prevent it from leaking into the `terraform apply` CLI logs.

## Usage

```hcl
module "secret_consumption_demo" {
  source = "./modules/example_secret_consumption"

  app_name               = "my-secure-app"
  db_password_secret_arn = "arn:aws:secretsmanager:us-east-1:123456789012:secret:db-pass-abcd"
  api_token_vault_path   = "secret/data/my-secure-app/api_token"
}
```
