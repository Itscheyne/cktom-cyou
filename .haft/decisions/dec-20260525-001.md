# Longhorn

## 1. Problem Frame

**Signal:** Talos Linux is immutable — no host-level storage daemons. Need a CSI-compatible persistent storage solution for workloads on Proxmox-hosted Talos nodes.

**Constraints:**
- Must work with Talos Linux (no OS package installs, no SSH, immutable rootfs)
- Must be CSI-compatible (standard PVC provisioning)
- Runs on Proxmox VMs (no bare-metal assumptions)
- Single homelab operator — no enterprise support budget

**Acceptance:** CSI StorageClass provisioned, PVCs bound, data survives pod reschedule and single-node failure

## 2. Decision

**Selected:** Longhorn

**Selection policy:** Minimize ops burden for solo homelab operator. Prefer data durability over performance. Prefer no Talos extensions if ops complexity equal. Break ties on maturity.

**Why selected:** Best balance of maturity, in-cluster replication, and ops complexity for solo homelab operator. CNCF graduated with large homelab community. No external NAS dependency. RWX available via NFS-backed volumes. Extension rebuild cost is one-time per Talos upgrade and well-documented.


**Invariants:**
- CSI StorageClass must provision PVCs without manual intervention
- Data must survive single-node failure (minimum 2 Longhorn replicas)
- Longhorn must run as Kubernetes workloads only — no host daemons

**Pre-conditions:**
- [ ] Talos node images rebuilt with iscsi-tools and util-linux-tools extensions via Image Factory
- [ ] Minimum 3 worker nodes available for replica distribution
- [ ] Dedicated disk or partition available on each node for Longhorn storage

**Post-conditions:**
- [ ] Longhorn StorageClass exists and is default
- [ ] Test PVC binds successfully
- [ ] Test pod with PVC survives deletion and reschedule to different node with data intact
- [ ] Longhorn UI accessible via ingress or port-forward

**Admissibility:**
- NOT: Must not use shell scripts or host daemons on Talos nodes
- NOT: Must not require SSH access to nodes
- NOT: Must not use command/shell model as storage integration workaround

## 3. Rationale

**Counterargument:** democratic-csi + TrueNAS gives stronger durability (data survives full cluster destruction) with no extension burden. If the homelab ever needs a full cluster rebuild, Longhorn data is gone with the cluster.

**Selected variant weakest link:** Two Talos system extensions (iscsi-tools, util-linux-tools) must be baked into node image via Image Factory on every Talos upgrade. Miss the rebuild → volumes go offline.

**Rejected alternatives:**
| Variant | Verdict | Reason |
|---------|---------|--------|
| Longhorn | **Selected** | Best balance of maturity, in-cluster replication, and ops... |
| democratic-csi + NFS/iSCSI | Rejected | Requires maintaining a separate NAS — adds another system to ops. NAS is hard SPOF for all PVCs. Better fit if TrueNAS already exists in the homelab. |
| Proxmox CSI Plugin | Rejected | RWO only — no RWX support. Vendor-locked to Proxmox. Newer, less mature project. API-gated volume attach adds scheduling latency. |
| Rook/Ceph | Rejected | Highest ops complexity. Requires Ceph expertise, dedicated OSD RAM budget, rbd extension. No homelab-relevant advantage over Longhorn. |
| local-path-provisioner | Rejected | Zero durability. Node failure = data loss. Dominated by Proxmox CSI on all target dimensions. |

**Evidence requirements:**
- Confirm Talos Image Factory produces valid image with iscsi-tools + util-linux-tools for current Talos version
- Verify Longhorn Helm chart deploys cleanly on Talos (check talos.dev docs or community reports)
- Test PVC survives node drain/reschedule cycle

**Predictions:**
| Claim | Observable | Threshold |
|-------|------------|-----------|
| PVC survives node failure | Cordon + drain one node; pod reschedules; data intact | 100% data preserved, pod running within 5 minutes |
| Extension rebuild is manageable | Talos upgrade completes with new image factory image including extensions | No volume downtime beyond planned maintenance window |

## 4. Consequences

**Rollback plan:**
Triggers:
- Longhorn extension rebuild blocks Talos upgrade for >1 week
- Longhorn volumes become corrupt or unrecoverable
- Memory/CPU overhead exceeds available node resources
Steps:
1. Backup all PVC data via Longhorn snapshot + S3 export
2. Migrate workloads to temporary local-path StorageClass
3. Uninstall Longhorn Helm release and CRDs
4. Rebuild Talos images without iscsi-tools/util-linux-tools extensions
5. Deploy replacement storage (democratic-csi or Proxmox CSI)
Blast radius: All stateful workloads — requires coordinated maintenance window

**Refresh triggers:**
- Talos major version upgrade
- Longhorn drops iscsi dependency (future versions may use NVMe-oF)
- NAS added to homelab (re-evaluate democratic-csi)
- Cluster expands beyond 5 nodes (re-evaluate Rook/Ceph ROI)
